

> 目前小米应用商店要求上架 App 提供“软件著作权证明”和“APP 备案”，普通个人开发者也不能完全绕过这两项。

下面按实际操作顺序说明。

---

# 一、先准备必要资质

## 1. 小米开发者账号

进入：

[小米澎湃 OS 开发者平台](https://dev.mi.com/)

注册或登录小米账号，然后选择应用分发。

开发者主体一般有：

* 个人开发者
* 企业开发者

个人开发者可以发布普通工具类 App，但如果准备长期商业化，建议使用企业主体。

账号资料要保持真实一致：

* 姓名或企业名称
* 身份证信息
* 联系电话
* 联系邮箱
* 收款账户
* 营业执照信息——企业账号

小米发布协议明确要求开发者信息真实、合法、准确、完整，账号也不能随意转让或借给别人使用。

---

## 2. 计算机软件著作权

小米当前资质 FAQ 显示，所有应用上架需要提供以下任意一种：

* 《计算机软件著作权登记证书》
* 《APP 电子版权证书》
* 《软件著作权认证证书》

建议直接办理：

> 《计算机软件著作权登记证书》

准备材料通常包括：

* 软件名称
* 版本号
* 软件功能说明
* 软件源代码部分页面
* 软件操作说明
* 著作权人信息
* 身份证明或营业执照

注意 App 名称要尽量统一：

```text
App 名称 = 软件著作权名称 = APP备案名称
```

如果以后修改 App 名称，软著和 APP 备案通常也要同步修改。

---

## 3. APP 备案

小米现在要求所有上架应用提供 APP 备案信息。

备案时需要重点保持以下内容一致：

* App 主办单位
* App 名称
* App 包名
* 服务备案号

例如：

```text
主办单位：张三
App 名称：我的工具
包名：com.example.mytool
```

这几个信息不能随便改。

小米还要求在 App 内展示服务备案号，而不是只展示主体备案号。

### 建议顺序

先确定：

```text
App 名称
包名 applicationId
开发者主体
软件著作权名称
APP备案名称
```

再办理软著和备案。否则后期改名会比较麻烦。

---

# 二、准备可上传的 Android 安装包

小米应用商店提交指南目前使用 APK 上传流程。

准备：

```text
app-release.apk
```

必须是：

* Release 版本
* 正式签名
* 非 Debug 包
* 没有测试服务器入口
* 没有开发者菜单
* 没有测试广告
* 包名与后台创建的包名一致
* Version Code 正确递增

### 签名文件一定要保存

妥善保存：

```text
upload-key.jks
密钥库密码
key alias
key 密码
```

小米文档也特别提醒，应用签名是应用的关键性信息，丢失后会影响后续更新。

不要把签名文件提交到 GitHub。

---

# 三、准备隐私合规内容

小米审核会关注：

* 隐私政策
* 用户协议
* 权限申请
* SDK 使用
* 个人信息收集
* 广告内容
* 用户注销和数据删除
* 是否存在恶意行为

小米发布协议要求开发者尊重用户知情权和选择权，在 App 中展示隐私政策并获得用户同意。

## 你的 App 启动流程建议这样做

首次启动：

1. 显示隐私政策和用户协议
2. 用户点击同意
3. 再初始化第三方 SDK
4. 再申请相机、存储、定位等权限
5. 再发送设备信息或网络请求

不要出现这种情况：

```text
App 启动
↓
立即初始化广告 SDK
↓
立即读取设备信息
↓
最后才弹隐私协议
```

这很容易被检测工具发现。

对于你的图书盘点 App，还要特别检查：

* 相机权限
* 图片读取权限
* 网络访问
* FTP 账号密码
* 图片上传
* 设备信息
* OCR/AI SDK
* 崩溃统计 SDK
* 是否将书架照片上传到服务器

如果使用 AI 生成、AI 对话、人脸生成、图像生成等功能，可能还涉及安全评估和算法备案。普通 OCR 识别不一定等于生成式 AI，但要根据实际功能判断。小米当前资质说明对生成式 AI、人脸、人声等功能提出了额外要求。

---

# 四、注册并创建应用

登录小米开发者平台后：

1. 进入“应用分发”
2. 选择“小米手机及平板”
3. 点击“创建应用”
4. 选择默认语言
5. 选择 Android
6. 填写应用名称
7. 填写包名
8. 创建应用

创建成功后，小米会生成：

* App ID
* AppKey
* AppSecret

这些信息主要用于接入小米 SDK 和开放服务。

注意：

> 创建应用不等于已经上架。创建只是建立应用档案，必须完成资料填写和审核提交。

---

# 五、填写应用资料

小米提交指南要求填写：

* 应用名称
* 版本号
* 开发者名称
* 应用分类
* 关键字
* 一句话简介
* 应用介绍
* 隐私政策
* 官网——可选
* 更新日志
* 测试账号——如需要
* 应用截图
* 软件著作权
* APP 备案
* 相关行业资质

小米官方要求关键字必须与应用功能相关，不能放无关竞品名称；一句话简介不能使用“第一”“唯一”“最强”“必备”等夸张或极限词。

## 应用截图

通常至少准备 3 张截图。

如果选择“手机和平板”，需要分别准备：

* 手机截图
* 平板截图

小米指南还要求：

* 不要上传重复截图
* 不要出现其他应用商店首发字样
* 截图应真实展示功能
* 截图方向要正确

---

# 六、上传 APK

在应用详情页：

1. 点击“立即上传”
2. 选择正式签名 APK
3. 等待上传完成
4. 检查系统读取的信息：

   * 包名
   * 应用名称
   * Version Name
   * 文件大小
5. 填写应用类型：

   * 手机
   * 平板
   * 手机和平板
6. 选择应用分类
7. 设置发布地区
8. 填写应用描述
9. 上传截图
10. 上传软著和 APP 备案资料
11. 保存并提交

小米当前指南显示，可选择的分发地区包括：

* 中国大陆
* 台湾地区
* 香港地区

如果 APK 大于 50 MB，小米指南建议使用“大文件发布助手”。

---

# 七、提交审核

检查无误后点击“提交”。

小米官方提交指南显示，应用通常会在 1～3 个工作日内审核；超过 3 个工作日没有反馈，可以联系：

```text
developer@xiaomi.com
```

审核结果一般包括：

* 审核通过
* 审核不通过并给出原因
* 要求补充资质
* 要求修改 App
* 要求重新上传 APK

如果被拒，不要马上重新创建一个新应用。通常应在原应用基础上修改后重新提交。

---

# 八、小米应用市场的变现方式

## 方式一：米盟广告

小米提供“小米移动广告联盟”，支持：

* 开屏广告
* 横幅广告
* 插屏广告
* 视频广告
* 原生广告

官方流程是：

1. App 在小米应用商店成功上架
2. 签约成为米盟开发者
3. 集成广告 SDK
4. 配置广告位
5. 启动广告位
6. 开始变现

### 广告接入注意事项

开发阶段使用测试广告，正式发布前切换正式广告位。

不要：

* 自己点击广告
* 让亲友集中点击
* 用按钮诱导点击广告
* 把广告伪装成系统提示
* 频繁弹出插屏
* 在用户刚启动时连续显示广告
* 展示违法、赌博、色情或虚假广告

对工具类 App，比较稳妥的是：

* 底部 Banner
* 完成一次操作后偶尔插屏
* 高级功能使用激励视频
* 付费购买后去广告

---

## 方式二：小米应用内支付

小米提供 IAP SDK，可以支持：

* 消耗型商品
* 非消耗型商品
* 游戏道具
* 高级功能
* 永久解锁
* 会员权益

官方文档要求的基本流程是：

```text
创建商品
↓
查询商品
↓
发起购买
↓
服务端验证订单
↓
发放权益
↓
调用 finishPurchase
```

小米建议通过服务端接收和验证购买结果，而不是只依赖客户端返回值。

### 重要限制

当前小米 IAP 文档提到，接入前可能需要：

* 注册开发者账号
* 创建应用或游戏
* 联系商务配置白名单
* 配置商品和计费点

因此不要一开始就假设普通工具 App 可以直接使用全部 IAP 能力。先在开发者后台确认你的应用类型是否开放。

---

## 方式三：自建会员或 SaaS 服务

例如：

* 企业版授权
* 云端存储
* B2B 服务
* 设备管理平台
* 图书馆管理后台
* 企业订阅
* 私有化部署

对于你的图书盘点 App，更合适的商业模式可能是：

```text
App 免费下载
+
企业账号/后台服务收费
+
图片存储或 OCR 服务收费
+
定制开发收费
```

但如果 App 内部直接解锁数字功能并收费，最好先确认小米当前平台规则和支付方案，不要未经确认就直接加入支付宝、微信支付或外链收款。

小米发布协议写明，未经小米书面同意，发布者不得就其发布作品向用户收取费用。

---

# 九、收款和结算

如果使用米盟广告或小米 IAP，需要在平台中完成：

* 开发者主体认证
* 财务信息填写
* 收款账户绑定
* 税务或发票信息
* 结算协议签署

个人和企业的结算资料可能不同。具体结算周期、门槛、分成比例和发票要求，应以开发者后台当前协议为准。小米官方提供单独的“结算流程”和“财务结算常见问题”文档。

建议使用：

* 个人银行卡——个人主体
* 企业对公账户——企业主体

不要使用他人银行卡，否则容易出现结算失败、主体不一致或税务问题。

# 十、常见拒审原因

## 1. 没有软著

小米当前规定，软著是上架必要资质之一，办理中通常不能先上架。

## 2. 没有 APP 备案

目前所有应用上架都需要提供 APP 备案。

## 3. 三个名称不一致

例如：

```text
App：图书盘点助手
软著：图书盘点助手
备案：图书盘点
```

这种可能需要先修改资料。

## 4. 包名不一致

后台创建的包名必须和 APK 内的包名完全一致：

```text
com.example.bookinventory
```

不能出现大小写、后缀或字符差异。

## 5. 首次启动就读取隐私信息

常见问题：

* 还没同意隐私协议就初始化 SDK
* 还没授权相机就读取设备信息
* 还没同意就发送网络请求
* 直接读取剪贴板
* 过度申请存储权限

## 6. 权限与功能不匹配

例如一个普通计算器要求：

* 通讯录权限
* 电话权限
* 定位权限
* 短信权限

会非常可疑。

## 7. 应用无法正常使用

包括：

* 启动崩溃
* 登录失败
* 服务器不可访问
* 图片上传失败
* 页面显示空白
* 必须使用特殊网络才能运行
* 测试账号失效

## 8. 应用介绍夸大

避免：

* 第一
* 最强
* 全球领先
* 100% 准确
* 永不丢失
* 官方指定
* 完全免费——实际存在收费功能

## 9. 使用侵权内容

包括：

* 未授权字体
* 未授权音乐
* 网络图片
* 他人 App 图标
* 竞品截图
* 小米 logo 或系统图标的误用

## 10. 集成高风险功能但没有资质

例如：

* 新闻聚合
* 直播
* 社区评论
* 在线交友
* 地图导航
* 医疗诊断
* 金融服务
* 生成式 AI
* 人脸生成
* 网络游戏

这些功能可能需要额外许可证、备案或安全评估。

# 十一、针对你的图书盘点 App 的建议

你的 App 主要涉及：

* 相机
* 图片管理
* OCR
* FTP 上传
* 图书位置管理
* 可能的服务器账号登录

建议第一版先做成：

```text
本地拍照
+
本地照片管理
+
手动上传
+
基础 OCR
```

暂时不要在第一版加入：

* 复杂会员体系
* 在线社区
* 用户评论
* AI 生成内容
* 人脸识别
* 过多第三方 SDK
* 复杂支付系统

这样更容易通过审核。

上架前重点准备：

* 软件著作权
* APP 备案
* 隐私政策
* FTP 密码加密存储
* 用户注销和数据删除说明
* 相机和图片权限说明
* OCR 数据处理说明
* 服务器安全说明
* 至少 3 张真实截图
* 正式签名 APK

# 十二、推荐的实际时间安排

### 第 1 步：确定产品资料

```text
App 名称
包名
开发者主体
版本号
应用分类
```

### 第 2 步：办理资质

```text
软件著作权
APP备案
```

### 第 3 步：完成隐私合规

```text
隐私政策
用户协议
权限申请
SDK 清单
用户注销
```

### 第 4 步：创建小米开发者账号

```text
dev.mi.com
```

### 第 5 步：创建应用并上传 APK

填写资料、截图和资质。

### 第 6 步：提交审核

一般等待 1～3 个工作日。

### 第 7 步：审核通过后再接入变现

建议顺序：

```text
先上架
↓
确认应用稳定
↓
接入米盟广告
↓
有用户后再接入 IAP 或企业收费
```

最稳妥的起步方式是：

> 小米开发者个人账号或企业账号 + 正式签名 APK + 软著 + APP 备案 + 免费上架 + 米盟广告。

对你的图书盘点 App，则更建议：

> 免费 App + 企业版服务收费 + OCR/云端功能收费，而不是一开始就做复杂的个人用户内购。
